# Развёртывание и эксплуатация

## 1. Среды

| Среда | Назначение |
| --- | --- |
| Local | Разработка и интерактивная проверка мобильного прототипа |
| Production prototype | Статическая сборка на `probaclinical.ru` |
| Future staging | Backend, платежи и лабораторные адаптеры на тестовых данных |

## 2. Локальная проверка

```bash
npm ci
npm run check:runtime
npm run dev
```

Перед публикацией:

```bash
npm run check:runtime
npm run build
npm run test:runtime
npm run test:sites
```

Проверка должна завершиться без ошибок TypeScript, без незарегистрированных изменений защищённого мобильного runtime и с успешно пройденными тестами адаптивной вёрстки.

## 3. Production prototype

- сервер: VPS Timeweb;
- web-сервер: Caddy;
- каталог проекта: `/opt/proba-miniapp`;
- активная версия: `/opt/proba-miniapp/current`;
- архивы релизов: `/opt/proba-miniapp/releases/<timestamp>`;
- конфигурация сайта: отдельный блок `probaclinical.ru, www.probaclinical.ru`;
- DNS apex и `www`: A → `64.188.58.140`;
- HTTPS: автоматически выпускается и продлевается Caddy.

Пока новый домен проходит первичную публикацию в зоне `.ru`, Telegram использует временный HTTPS-адрес `https://proba.64-188-58-140.nip.io` и для кнопки меню, и для Main Mini App. Он обслуживается тем же Caddy и той же production-сборкой. После готовности брендового домена оба адреса необходимо заменить на `https://probaclinical.ru`.

На сервере также работают другие проекты. Нельзя менять их каталоги, процессы или существующие блоки Caddy.

## 4. Безопасная публикация

1. Запустить production-сборку локально.
2. Создать новый каталог релиза, не перезаписывая активный.
3. Синхронизировать только содержимое `dist/client`.
4. Сравнить число и контрольные суммы файлов.
5. Атомарно переключить символическую ссылку `current`.
6. Проверить `probaclinical.ru`, ассеты и SPA fallback.
7. Повторно проверить соседние сайты.

Секреты из `probaCreds.md` не копируются в репозиторий и не нужны статической сборке.

## 5. Откат

1. Найти предыдущий каталог в `/opt/proba-miniapp/releases`.
2. Переключить `/opt/proba-miniapp/current` на предыдущую версию.
3. Проверить главную страницу и загрузку ассетов.
4. Не удалять неудачный релиз до выяснения причины.

Откат frontend не требует изменения Caddy или соседних сервисов.

## 6. DNS и HTTPS

Через API Timeweb должны существовать записи:

```text
probaclinical.ru      A  64.188.58.140
www.probaclinical.ru  A  64.188.58.140
```

После появления записей на авторитетных NS необходимо дождаться успешного TLS-выпуска, затем проверить:

- HTTPS-код `200`;
- заголовок `content-type: text/html`;
- загрузку JS и CSS;
- открытие вложенного SPA-пути;
- отсутствие TLS-ошибок;
- сохранение доступности соседних сайтов.

## 7. Telegram

В BotFather/Bot API настроены описание, команды, кнопка меню и Main Mini App. Для текущего временного production-адреса Bot API должен возвращать `has_main_web_app: true`. После готовности брендового HTTPS:

- установить кнопку меню на `https://probaclinical.ru`;
- указать тот же URL как Main Mini App;
- проверить запуск из Telegram на реальном телефоне;
- отдельно реализовать обработчик `/start` на backend;
- проверять `initData` на сервере перед доступом к пользовательским данным.

Frontend подключает официальный Telegram Web App SDK и при запуске:

- вызывает `ready()` и `expand()`;
- для Bot API 7.7+ вызывает `disableVerticalSwipes()`;
- для Bot API 8.0+ вызывает `requestFullscreen()`;
- сохраняет системную кнопку закрытия Telegram;
- использует динамическую высоту viewport и CSS-переменные safe area/content safe area;
- оставляет защитную верхнюю зону не меньше 64 px, чтобы собственные элементы не перекрывали системные кнопки Telegram;
- показывает production-интерфейс без рамки устройства; рамка iPhone/Pixel остаётся только в изолированном тестовом стенде runtime.

Telegram оставляет за собой нативный жест по собственной верхней панели: Mini App может отключить свайпы по своему содержимому, но не может программно отменить системный жест клиента.

Статический прототип не обрабатывает команды и не принимает реальные платежи.

## 8. Контроль после публикации

- главная страница и ассеты отвечают `200`;
- сертификат действителен для apex и `www`;
- Caddy находится в состоянии `active`;
- два соседних проекта отвечают так же, как до изменения;
- Telegram-кнопка открывает Mini App без предупреждения;
- в браузерной консоли нет ошибок.
